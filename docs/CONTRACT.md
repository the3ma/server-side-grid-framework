# Grid contract

The single source of truth that the backend (`src/GridKit`, `src/SampleApi`) and the frontend
(`web/`) implement. If code and this file disagree, fix the code or change this file in the same
pull request.

## Domain (example)

A **warehouse shipment tracker** in a data portal with role-based access: every shipment that
leaves a warehouse is one row. Users browse it in a server-side grid. All data is synthetic and
generated by the seed.

### Table `shipment` (SQLite in the runnable demo)

| Column | Type | Notes |
|---|---|---|
| `shipment_id` | `INTEGER PRIMARY KEY` | unique tiebreaker |
| `tenant_id` | `INTEGER NOT NULL` | **row scope**: a user only ever sees their tenant |
| `tracking_no` | `TEXT NOT NULL` | always upper-case (`TRK-0001234`), indexed |
| `warehouse_code` | `TEXT NOT NULL` | always upper-case (`WH-104`), indexed |
| `destination` | `TEXT NOT NULL` | mixed case, not indexed |
| `status` | `TEXT NOT NULL` | `received`, `in_transit`, `delivered`, `returned`, `cancelled`; indexed |
| `carrier` | `TEXT NULL` | `Northline`, `Parcelway`, `Bluecrate`, `Swiftlane`, `Overland` |
| `weight_kg` | `REAL NULL` | |
| `shipped_at` | `TEXT NOT NULL` | ISO-8601 UTC `YYYY-MM-DDTHH:MM:SSZ` |
| `delivered_at` | `TEXT NULL` | ISO-8601 UTC; the proof-of-delivery record date |
| `flagged` | `INTEGER NOT NULL` | `1` / `0` |
| `price_tier` | `TEXT NULL` | `standard` / `discount` / `contract`; **restricted** to the finance role |

Indexes: `(tenant_id, tracking_no)`, `(tenant_id, warehouse_code)`, `(tenant_id, status)`.
Seed: 120 000 rows over 3 tenants (tenant 1 has 80 000), deterministic (fixed random seed).

## Endpoints

```
POST /api/shipments/grid          body: GridRequest        -> 200 GridPage<ShipmentRow>
POST /api/shipments/grid/values   body: GridValuesRequest  -> 200 GridValuesPage
GET  /api/health                                           -> 200 { status: "ok" }
```

Identity comes from the authenticated principal, never from the body. The demo authentication
handler signs every request in as tenant 1; header `X-Demo-Tenant: 2|3` switches tenant and
`X-Demo-Finance: true` adds the `finance` role (demo only, documented as such).

## `GridRequest`

| Member | Rule |
|---|---|
| `page` | int, 0-based, `>= 0` |
| `pageSize` | int `1..500`, default `100` |
| `sort` | `[{ field, dir: "asc" \| "desc" }]`, max 3, no duplicate field; the server always appends the tiebreaker |
| `filters` | `{ [field]: { type, op, value?, valueTo?, values? } }`, **one condition per field**, max 50 fields |
| `search` | optional string, max 200; OR of `contains` across the searchable text columns |
| `timeZone` | IANA id; required only when a `local` date column is filtered |
| `includeTotal` | bool, default `true`; `false` skips the count query and returns `totalCount: null` |

### Filter types and operators

| `type` | `op` | value |
|---|---|---|
| `text` | `contains`, `notContains`, `equals`, `notEqual`, `startsWith`, `endsWith`, `blank`, `notBlank` | `value`: string, 1..200 |
| `number` | `equals`, `notEqual`, `lessThan`, `lessThanOrEqual`, `greaterThan`, `greaterThanOrEqual`, `inRange`, `blank`, `notBlank` | `value` number; `valueTo` for `inRange` (both ends inclusive) |
| `date` | same as `number` | `YYYY-MM-DD`, `>= 1753-01-01`; half-open day ranges (below) |
| `set` | `in` | `values: string[]`, max 1000; `[]` matches nothing; whole numbers only on an integer-valued column |
| `boolean` | `equals`, `blank`, `notBlank` | `value`: `true` / `false` |

`blank` / `notBlank` take no value. Negative text operators (`notContains`, `notEqual`) include
blanks; number/date `notEqual` excludes nulls.

### Dates

| Semantics | Day boundaries | Used for |
|---|---|---|
| `utc` | UTC midnight; the request `timeZone` is ignored | record dates such as proof of delivery (`deliveredOn`) |
| `local` | the user's local midnight in `timeZone`, converted to UTC; DST-safe | operational dates (`shippedOn`) |
| `calendar` | plain date | day-valued columns |

All operators are half-open: `equals d` -> `>= start(d) AND < start(d+1)`;
`lessThanOrEqual d` -> `< start(d+1)`; `greaterThan d` -> `>= start(d+1)`;
`inRange a..b` -> `>= start(a) AND < start(b+1)`.

## `GridPage<T>`

```json
{
  "rows": [ { "shipmentId": 1, "trackingNo": "TRK-0000001", "...": "..." } ],
  "totalCount": 80000,
  "capabilities": { "textFilters": "disabled", "reason": "resultSetTooLarge", "threshold": 50000 }
}
```

`totalCount` is `null` (never `0`) when `includeTotal` was `false`. `capabilities` is always present.

## `GridValuesRequest` / `GridValuesPage`

`{ field, search?, filters, timeZone? }` -> `{ values: string[], truncated: boolean }`.
`field` must be a filterable `set` column. `filters` are the grid's other filters (the field's own
filter is ignored); `search` scopes the rows the values come from (same meaning as in
`GridRequest`). At most 1000 distinct, non-null values, sorted; `truncated` when there were more.

## Columns of the `shipments` grid

Field ids are camelCase (`^[a-z][A-Za-z0-9]{0,63}$`) on both sides.

| Field | Type | Expression | Flags |
|---|---|---|---|
| `shipmentId` | number | `g.ShipmentId` | sortable, filterable, indexed |
| `trackingNo` | text | `g.TrackingNo` | sortable, filterable, searchable, indexed, storedUpperCase |
| `warehouseCode` | set | `g.WarehouseCode` | sortable, filterable, indexed |
| `destination` | text | `g.Destination` | sortable, filterable, searchable |
| `status` | set | `g.Status` | sortable, filterable, indexed |
| `carrier` | set | `g.Carrier` | filterable |
| `weightKg` | number | `g.WeightKg` | sortable, filterable |
| `shippedOn` | date, `local` | `g.ShippedAt` | sortable, filterable |
| `deliveredOn` | date, `utc` | `g.DeliveredAt` | sortable, filterable |
| `flagged` | boolean (`1`/`0`) | `g.Flagged` | filterable |
| `priceTier` | set | `g.PriceTier` | filterable, **restricted** (only with the `finance` role) |

Tiebreaker `g.ShipmentId`; default sort `shippedOn desc`; large-dataset guard threshold `50 000`.

### Large-dataset guard

With a threshold set, `contains`, `notContains` and `endsWith` text filters and `search` are
refused with `400 grid-filter-too-broad` unless the request also has a **selective** filter on an
indexed column (any operator except `contains`, `notContains`, `endsWith`, `blank`, `notBlank`,
`notEqual`), or the server knows the scoped set is at or under the threshold. Every page reports
`capabilities.textFilters` so the UI can remove the guarded operators and say why.

### Restricted columns

A restricted column is an **unknown field** (400 `unknownField`) for filter, sort and values for
every caller, unless the server opens it for that caller. The base SQL also returns it as `null`
unless the caller has the `finance` role.

## Errors (RFC 7807 ProblemDetails, `application/problem+json`)

| Status | `type` | Extensions |
|---|---|---|
| 400 | `grid-request-invalid` | `errors: { [key]: string[] }`, `errorCodes: { [key]: string[] }` |
| 400 | `grid-filter-too-broad` | `fields: string[]` (`search` for the quick search), `threshold` |
| 504 | `grid-query-timeout` | `timeoutSeconds` |
| 500 | `grid-query-failed` | none |

Every response carries `traceId`. Error keys are allow-listed field ids, request member names
(`page`, `pageSize`, `sort`, `search`, `timeZone`, `filters`, `field`) or `(invalid field)` for a
malformed key. **Messages and keys never contain request values.** A database value-conversion
error is re-thrown value-free; the driver exception is never chained or logged.

Error codes: `unknownField`, `notSortable`, `notFilterable`, `typeMismatch`, `unsupportedOperator`,
`valueRequired`, `valueNotAllowed`, `invalidValue`, `tooLong`, `tooMany`, `outOfRange`,
`duplicate`, `timeZoneRequired`, `invalidTimeZone`, `notSetColumn`.

## Manifest

`GridManifest.From(map)` writes a SQL-free JSON description of the column map to
`docs/manifest/shipments.json` (written by a backend test). The frontend test compares its column
declaration with that file, so the two sides cannot drift apart unnoticed.

```json
{ "grid": "shipments", "threshold": 50000, "defaultSort": [{ "field": "shippedOn", "dir": "desc" }],
  "columns": [ { "field": "trackingNo", "type": "text", "sortable": true, "filterable": true,
                 "searchable": true, "indexed": true, "restricted": false,
                 "ops": ["contains", "..."], "dateSemantics": null } ] }
```
